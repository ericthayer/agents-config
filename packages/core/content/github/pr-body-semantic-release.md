# Release pull request

Follow the repository's release policy and conventional commit configuration.
Version numbers and changelogs are consumer-facing contracts.

## Summary

Describe added capabilities and corrected behavior.

## Compatibility and migration

Identify breaking changes, supported versions, and required consumer actions.
Do not deprecate a package without an approved migration path.

## Release readiness

Record actual validation results, required registry permissions, and release
prerequisites. Do not include secrets.

## Rollback

Document how consumers can return to the previous compatible version and what
data or configuration changes require special handling.
